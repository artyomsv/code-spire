stable ID on save. GitHub/GitLab exact matches differ from Bitbucket/Jira explicit candidate
selection. Directory reads reject a foreign-origin redirect, including one to a different port
on the same host. No live account receives elevated permissions. Adapter exception bodies do
not reach API responses; each forge has its own UNVERIFIED entry.

ActorResolutionResourceTest.handleEntryStoresStableIdAndReturnsHandle exercises authenticated
HTTP plus real database storage. It asserts the actual provider_author.author value, launches a
fresh JVM using the production ActorPolicyRegistry to read it, lets that JVM exit, then launches
another reader and checks the same ID/handle. It finally reads the HTTP view again. This proves
persistence across reader-process restart, not a restart of the full Quarkus stack. All fixtures
are TEST-labelled rows in disposable Dev Services, with explicit repository binding/repository/
account DELETE cleanup. No synthetic row is written to the live dev database.

Repository overrides are unique per actor, hold ALLOW or DENY, and require the stored revision
for contradictory edits or deletion. Save locks the selected account and repository binding.
Account policy entries prevent changing the account's forge kind or origin while referenced.
Legacy numeric GitHub/GitLab IDs or stable IDs observed on the repository's actual review history
become grants; unresolved strings receive no new authority. Slice 4 activates the new permission
fallback and must retain all existing target/spend constraints.

The UI resolves before saving and reloads observed handles rather than a count or raw ID. The
account Policy cell shows people, effects and stale observations. The reusable person control
also supports source credentials; work-source registration itself is introduced in slice 5, so
source-screen integration is recorded there rather than claimed present now. Account policy
must not be silently inherited by work-source authorization.
