## Resolved (fixed in code; do not re-raise)
- [cr-C1] A run that never reached its agent was charged, and the row consumed the deployment-wide CALL cap. `BAD_COMMAND`, `RUNTIME_UNAVAILABLE` and `CLONE_FAILED` are raised before `runtime.create`, so no agent and no tokens — but each wrote a zero-token UNKNOWN row that `COUNT(DISTINCT call_ref)` counts. A daemon outage failing every dispatch in seconds would have spent the whole call budget on runs that bought nothing, and that budget refuses REVIEWS too. On an UNMETERED deployment the call axis is the only axis, so it would be the entire cap. `RunFailureCause` gained an `agentMayHaveSpent` axis defaulting to TRUE, so only a cause that provably precedes the agent is skipped and measured usage always overrides — round 1
- [sec-M1] The spend cap now consumes an agent-influenced number. The harness parses usage from a container the agent runs shell in at full access, so a fabricated multi-billion-token line prices high enough for `SpendGate` to refuse every paid call until the window drains — taking out the reviewer as well as the factory, from one run. `SPIRE_RUN_MAX_REPORTED_TOKENS` bounds it: above the ceiling the call records UNKNOWN rather than priced, and is not discarded, so the mitigation cannot itself become a way to spend unseen. Unset means unlimited, matching every ADR-025 cap, and any non-positive value does too — zero is what an uninjected `long` field holds, and treating it as a real ceiling would let a non-CDI caller unprice every run — round 1
- [cr-I2] `runtime.destroy` was unguarded one line from a guarded `cancel` whose comment states the rule.
