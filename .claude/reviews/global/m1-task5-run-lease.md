## Resolved (fixed in code; do not re-raise)
- [sec-H1 / cr-C1] **A preserved unit's lease was heartbeated forever, so it could never go stale and the watchdog could never find it.** The sweep matched every lease its owner held, and skipping the DELETE left the row owned — so a preserved sandbox was refreshed every thirty seconds for the life of the replica. It became visible only after a restart, which is the one case where the lease was reapable anyway. Three javadocs and the commit message claimed the opposite. Preservation is now a STATE (`preserved_at`): the heartbeat skips a stamped row so it ages, and `staleLeases` reports it at once, because there is nothing left to wait for — round 1
- [sec-H2 / cr-C2 / rules-1 / qa-2] **The lease was released on four paths where the sandbox still existed**, each leaving a container holding a live model credential with no row naming it — the exact state the take-before-create ordering exists to prevent, undone twenty lines later. The dispatcher re-derived "was the unit destroyed" from the result's CAUSE while the launcher decided on `!finalization.salvaged()`. The paths: an init-container failure the Docker arm deliberately leaves behind, a throwing salvage after the publisher reported a push failure (`PUSH_REJECTED` and siblings), a throwing `destroy`, and anything escaping the observation loop. QA proved reachability against unmodified production code. Fixed by inverting the default: `RunObserver.unitReleased()` is called only where a teardown actually returned, so **silence means the unit is still there** and every unconsidered path leaks a row rather than a credential — round 1
