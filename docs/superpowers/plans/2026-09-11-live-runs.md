# Epic #147: live runs and run details

Source: [epic #147](https://github.com/artyomsv/code-spire/issues/147) and issues #133–#138.

## Implementation order

1. **#133 — Agent start time.** V58 adds nullable `agent_started_at`, without backfilling.
   Record the first observed `RunStarted` in the conditional status update. Carry it through both
   read models and the UI contract. Show queue time as **Queued**; list duration includes queue wait.
2. **#134 — Runs socket.** Add `/api/ws/runs`, with an explicit endpoint id, an unfiltered newest-200
   snapshot, and one-row pushes using the same SQL as the list. Every projection write must reach
   the broadcaster. A finished run and its subsequent PR proposal each push separately. Broadcast
   failures must not fail a committed write. Derive the write-coverage guard from source.
3. **#135 — Detail read model.** Expose the run definition, three timestamps, task summary, unknown-aware
   cost and spend split by token type. Exclude archived charges. No new prompt storage.
4. **#136 — Live list.** Follow `useLiveReviews` for socket lifetime, REST/socket race protection,
   session diagnosis and reconnect. Validate frames, sort by queue time and run id descending, and
   apply Kind/Status filters locally so pushed transitions can enter a filter.
5. **#137 — Detail page.** Use `/runs/*` and encoded links for ids containing `/` and `:`. Split the
   page into phases, runtime, spend, definition and task components. Refetch once when this run is
   pushed. Preserve unknown statuses and missing timestamps honestly. Include delivery, failures,
   all blocked paths, review links and a task-summary copy button.
6. **#138 — Event stream.** Consume the existing transcript socket with the run id in the query.
   Order and deduplicate by sequence. Provide All/Agent/System/Errors filters; unknown kinds belong
   to System. Auto-scroll follows the tail toggle and scroll position. Keep at most 2000 events,
   disclose dropped history and preserve clipping markers. A policy close is terminal; other
   reconnects follow the session-aware lifecycle.

The detail page splits recorded phases, runtime, spend, definition and task into components, with
conditional failure/blocked-path cards and a live event stream. The list and detail share the runs
socket transport; the detail performs one GET per relevant row frame and refreshes on snapshots,
including for old runs absent from the newest 200. Request sequencing rejects stale detail reads.
Unknown status stays warning-toned and never starts a clock; null cost stays a dash.

React Router already decodes the splat returned by `useParams`. Applying the issue's suggested
second `decodeURIComponent` would corrupt a literal `%41`, so the page uses the decoded splat
directly. Tests cover both real-shaped ids and this literal-percent case. Actual app navigation
uses its existing HashRouter (`#/runs/...`), while route declarations remain `/runs/*`.

The transcript merges its initial REST page and socket arrays by sequence, retains at most 2000
events, and keeps accumulated history across reconnect snapshots. Unknown kinds are System events;
Errors depends only on the error flag. Policy close 1008 is terminal, including against late REST
responses. Tail follows incoming events until the reader scrolls up, and resumes at the bottom or
when toggled on. Clipping markers are rendered as text.

**Scope correction for earlier history:** the existing REST route only returned the newest bounded
page, despite #138 promising that dropped events would be available there. The route now accepts an
optional exclusive `before` sequence cursor, retaining the same 2000 maximum and viewer access.
The disclosure links to the page preceding the oldest retained event. No transcript socket or
broadcaster is rewritten. A real REST test checks page boundaries, order, isolation from another
run, exhaustion and invalid cursors with identical timestamps across events.

`useLiveRuns` supplies the table from an unfiltered REST snapshot (limit 200) and `/api/ws/runs`.
Array frames replace state; identified objects upsert it. Queue time sorts descending, including
PostgreSQL's submillisecond precision, then run id descending. Kind and Status filter locally, and a
pushed transition can enter or leave the selected filter without a GET. The hook preserves the
reviews feed's session check, 1500ms reconnect delay, logout suppression and REST/socket race guard;
valid live data also clears an earlier REST error. Tests cover reconnect cleanup and StrictMode's
disposed socket as well as status, cost and PR updates in the table. The browser check above
verifies the integrated list/detail/transcript flow against the real orchestrator application.

The #134 socket tests perform a real HTTP upgrade and read JSON frames from the application while
writing to PostgreSQL. They cover the newest-200 unfiltered snapshot, queue/start/finish/proposal,
all other terminal statuses, both dispatch resolutions, re-arm, proposal failure and attention ack.
Plain tests check send/read failure isolation and skipping reads when nobody subscribes. The SQL for
`listOne` is shared with `list`, and both return the same record. Every existing plain projection fake
overrides `push` explicitly so an accidental real broadcast cannot silently pass. The charge fake
records expected spend notifications; the other fakes fail if an unexpected push reaches them.

The coverage guard parses Java syntax rather than comments. Deleting `push(result.runId())` in a
temporary source copy fails exactly the guard test and identifies `started`, `finished`, and `failed`
as uncovered writers. Production source remains intact during the probe.

**Spend delivery implemented with #135:** `RunResultSaga` deliberately projects the terminal outcome
before recording charges. `RunCharges` now pushes after the ledger write too. Real socket tests drive
priced FIX and delivered-nothing results through the saga: the first frame reports the outcome with
unknown cost, the second reports its priced total, and a detail read exposes the recorded token split.
Neither case opens a PR, so a proposal write cannot accidentally satisfy the test. A BUILD run that
also opens a PR now has three distinct updates: terminal outcome, recorded spend, and proposal.
The original outcome/proposal pushes remain separate; charges still cannot delay the outcome.

The widened detail record has one canonical construction site. `RunSpendReader` groups active RUN
charges by token type on the projection's connection. `RunSpend` carries the priced subtotal,
unpriced-line count and immutable token map; total cost is unknown for no lines or any unpriced line.
`RunDetailReadTest` covers every new REST field, all five split token types and TOTAL, repeated calls,
known zero, wholly/mixed unpriced usage, archived lines, another run's charges and a review charge
with the same textual id. No storage beyond #133's timestamp migration is added.

The checked-out Runs table had **neither Started nor Duration columns**, despite the issue describing
a rename. The implementation adds Queued and Duration. Duration is queue-to-end and remains unknown
until an end timestamp exists. Historic agent starts stay null.

The ordinary redelivery test alone cannot prove `COALESCE`: the existing WHERE clause rejects rows
already running. `RunAgentStartedTest` also seeds an eligible dispatch-recovery state with a recorded
start, then redelivers. The mutation probe compiles a temporary source copy under `build/`; it does
not alter production source.
