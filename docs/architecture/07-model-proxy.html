spire-model-proxy

It keeps the model credential away from the agent.

The agent sends plain HTTP to spire-model:8080 with a placeholder. The model proxy checks the path, puts in the real credential, and forwards the call to one vendor. The answer goes back with the secret masked.

What it is responsible for

  • It holds the real model credential for one run: an API key, or the access token and account id of a subscription seat.
  • It lets through only the paths that the harness adapter declared, for example /v1/messages for Claude Code.
  • It removes the credential headers that the agent sent, and adds the real ones.
  • It writes one log line for each request. The run worker reads the log when the run ends.

What it must never hold

  • The id token or the refresh token of a seat.
  • Any volume of the unit. It mounts nothing.
  • A route to any host other than the one vendor.

Rules it enforces

AreaRule
PathsExact paths, or whole-segment prefixes. It refuses .., ., //, a backslash, % and reserved characters.
MethodsGET and POST only. An absolute-form target gets 403. An upgrade or CONNECT gets 501.
Request headersIt drops Authorization, x-api-key, chatgpt-account-id, Cookie and Proxy-Authorization. It forces Accept-Encoding: identity.
AnswersA vendor 401 or 403 body is replaced with a fixed body. Response headers pass an allowlist. Location never passes. The secret is replaced with spire-model-withheld.
Limits8 requests at a time (503 above that), 8 MiB for a request body, 10 minutes idle, 60 minutes in total.

How the run worker reads the result

  • The log does not fail a run. The run worker reads it only after the agent has failed, to name the cause (RunLauncher.agentFailure).
  • A 401 on a model path names the cause CREDENTIAL_REJECTED, and the orchestrator marks that credential.
  • A refused path names the cause BLOCKED_EGRESS.
  • A 403 changes nothing. The cause from the harness adapter stays, and the credential is not marked.
  • A run that finished well stays finished, even if the proxy saw a 401.

How it is set up

Environment: SPIRE_MODEL_UPSTREAM, SPIRE_MODEL_INJECTION (BEARER, X_API_KEY or CHATGPT_SEAT), SPIRE_MODEL_PATHS_EXACT, SPIRE_MODEL_PATHS_PREFIX, SPIRE_MODEL_SECRET, SPIRE_MODEL_ACCOUNT.

The Docker runtime starts it (ModelProxyContainer) and waits up to 120 s for it to listen. It sits on two internal networks: one to the agent, one to the egress proxy.

Coupling to watch

  • Each harness adapter owns its route (CodexModelProxy, ClaudeCodeModelProxy). A new harness with no route runs without this proxy.
  • The log line format is a contract with ModelProxyReport in the run worker.
